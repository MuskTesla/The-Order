# 备份与回退

程序回退和用户资料回退是两个独立操作。替换或移除应用文件，不会主动迁移或删除游戏、存档或 Native Profile。

体验前先从托盘正常退出 The Order。若准备调整书架、账号、人工关联或新启动覆盖，请先备份整个 Native Profile，而不只导出书架 JSON。默认位置为 `%LOCALAPPDATA%/TheOrder/Profiles/Production`；显式自定义资料目录的用户应备份实际目录。它可能含 Windows 用户绑定的凭据，须由用户妥善保护，不能上传诊断报告。

新全局启动设置是可选的 `native-global-launch-v1.json`；首次缺失时全关，不为升级主动改写主库。没有新三态覆盖的旧安装继续保留原行为，旧 v1 编码不增加空 auxiliaries 字段。

用户保存新三态覆盖后，对应安装的原生扩展使用 v2。旧程序不理解 v2 时会明确拒绝写入／打开，不会安全地当成旧配置继续编辑；不要删除新字段或强制恢复旧缓存来绕过保护。已在合成资料中验证拒绝不改主文件、备份和 manifest，以及同一目录原地恢复升级前快照后的重新打开；这不是真实用户升级或旧版安装器验收。

需要回退时先退出候选，保留当前完整资料的另一份备份，再恢复已核验的旧程序。若旧程序拒绝新资料，应在**原资料目录**恢复升级前的完整快照，保留目录本身的物理身份，不把任意复制的新文件夹当作有效 Profile 克隆。恢复旧快照会移除快照之后新增的记录、设置和关联；先另存新快照，避免误以为这些改动仍存在。

本轮本机体验替换若已授权，程序回退副本和精确文件校验位置见本轮安装回执。开发测试不代替用户执行真实资料恢复，不自动把真实库复制进源码或试迁移。
